# Repository instructions

## Keep the public overview current

- Treat `README.md` as the public portfolio-project overview. Preserve its opening
  description unless the user asks to change it.
- Whenever a change adds, removes, or changes an implemented capability, its user-visible
  behavior, or the active tech stack, update the corresponding README section in the same
  change. Include this documentation check when finishing feature work.
- Describe what is actually wired into the runtime. Dependencies, reserved tool IDs,
  manifests, and scaffold files alone do not establish an implemented capability.
- Keep the README descriptive: tech stack and current capabilities. Put setup, run commands,
  environment configuration, and operational instructions in `docs/` instead.
- Keep personal account details and private deployment identifiers out of the public README.
